# 烹饪系统设计

## 文档范围

当前系统让玩家不依赖固定菜谱，通过组合食材、厨具、操作和加工程度自由制作料理。系统负责记录加工事实，并将组成、顺序、粗粒度状态和菜系倾向整理成模型可以理解的简洁提示词。

数据流水线、模型调用、持久化和工程架构另见 `实现.md`；餐厅经营及其他做菜外玩法另见 `经营.md`。

## 核心原则

- 代码记录食材和加工事实，不模拟完整料理结果。
- 加工历史保留先后顺序，供模型理解连续加工和重复加工。
- 三个粗粒度标签只帮助模型快速定位状态，不参与玩法评分。
- 菜系倾向继续使用确定性分数，但同一食材和同一厨具在整道菜中只计分一次。

## 核心循环

1. 选择厨具和该厨具支持的操作。
2. 将基础食材或已处理产物加入批次。
3. 为渐进式操作设置每个主体投入的加工程度。
4. 执行处理，消费已有产物并生成包含完整历史的新产物。
5. 将产物继续投入其他操作，形成连续加工。
6. 为最终保留的产物选择可选的成品结构角色。
7. 将组成、加工链、状态标签和菜系分数转换成模型提示词。

系统的基本操作单位是一次“厨具 + 操作 + 一批投入”的加工事件。

## 食材模型

每种基础食材包含：

| 属性 | 用途 |
| --- | --- |
| 名称 | 玩家看到的具体食材，例如牛肉、土豆、盐 |
| 展示分组 | 用于选择器分组 |
| 烹饪大类 | 判断操作兼容性和批次作用 |
| 物理特征 | 判断蛋白质、脂肪、水分、糖分和淀粉等操作条件 |
| 菜系分数 | 为最终料理提供菜系倾向 |

烹饪大类包括：

- 红肉、禽肉、鱼肉、贝类与软体海鲜、蛋
- 结实蔬菜、叶菜、谷物与面食、豆类、面团
- 乳制品、水果、葱蒜与香草、香辛料、坚果与种子
- 液体、油脂、调味料

### 加工中的食材作用

| 大类 | 作用 |
| --- | --- |
| 油脂 | 烹饪油脂 |
| 液体 | 液体 |
| 调味料 | 调味 |
| 香辛料 | 香辛料 |
| 葱蒜与香草 | 芳香配料 |
| 其他大类 | 主体食材 |

这组作用用于操作兼容性，不表示产物在最终料理中的摆放方式。

### 成品结构角色

每个已处理产物可以由玩家选择一个可选角色：

| 角色 | 含义 |
| --- | --- |
| 基底 / 载体 | 承载或衬托其他成分 |
| 主体 | 料理中主要的视觉与风味中心 |
| 覆盖 / 夹馅 | 覆盖、馅料或夹层 |
| 配菜 | 与主体分开搭配的辅助成分 |
| 汤汁 / 酱汁 | 汤底、浇汁、蘸汁或围边酱汁 |
| 点缀 | 少量装饰或提味成分 |

每次执行新加工后角色清空，由玩家按新产物用途重新选择。角色不参与兼容性和菜系计算。

## 厨具与操作

厨具决定可以发起哪些操作，部分厨具还提供菜系分数。

| 厨具 | 可执行操作 |
| --- | --- |
| 菜刀 + 砧板 | 对半、切片、切丝或条、切丁、切块、剁碎 |
| 擦丝器 | 擦碎 |
| 擀面杖 | 压扁、擀薄 |
| 研钵 | 压碎、研磨、捣成泥 |
| 搅拌碗 | 混合、打发、腌制 |
| 平底锅 | 煎或烙、焦糖化、烘香 |
| 炒锅 | 炒、烘香 |
| 汤锅 | 煮或汆煮、炖或焖 |
| 蒸锅 | 蒸 |
| 烤箱 | 烤制或烘焙 |
| 烤架 | 烧烤或炙烤 |
| 油炸锅 | 油炸 |
| 滤网 | 沥干 |
| 串签 | 穿串 |
| 压模 / 饼铛 | 压制成型、煎或烙 |
| 刷子 | 刷油、刷酱或挂汁 |

### 操作兼容性

每种操作声明主体大类和批次必要条件。例如：

- 切配主要接受固体食材。
- 焦糖化接受指定食材或具有糖分特征的食材。
- 煮和炖焖要求批次中包含液体。
- 油炸要求批次中包含油脂。
- 腌制要求调味料或香辛料。
- 刷酱或挂汁要求调味料。

批次中只要至少存在一个该操作支持的主体，其他投入就可以一同参与，并进入新产物的组成和历史。非主体投入不会获得该操作的程度。领域层在执行批次时仍会验证必要介质等批次条件。

## 操作类型

### 即时操作

即时操作没有程度档位：

- 切配：对半、切片、切丝或条、切丁、切块、剁碎、擦碎
- 形态：压扁、擀薄、压碎、研磨、捣泥、压制成型
- 组合：混合、打发、腌制
- 辅助：沥干、穿串、刷油、刷酱或挂汁

历史和提示词只记录操作名称，不额外生成结果描述。

### 渐进式操作

渐进式操作分为湿热和干热，并使用五档中性程度：

| 进度 | 文本 | 含义 |
| --- | --- | --- |
| `0/4` | 短暂 | 短暂接触式加工，例如快速涮煮 |
| `1/4` | 轻度 | 较轻的加工 |
| `2/4` | 常规 | 常规程度的加工 |
| `3/4` | 充分 | 较充分的加工 |
| `4/4` | 深度 | 深度加工，不预设好坏结果 |

湿热包括煮或汆煮、炖焖、蒸；干热包括煎或烙、炒、烘焙、烧烤、油炸、烘香和焦糖化。

档位只陈述本次加工事实。系统不把任何档位直接翻译为生鲜、熟透、焦黑或失败，具体结果交由模型结合完整顺序理解。

## 批次与加工链

一次加工可以接受多个投入：

- 所有投入共享厨具和操作。
- 每个主体投入可以设置自己的程度。
- 一个已处理产物作为投入时，其组成食材共享该投入的程度。
- 同一基础食材或同一个已处理产物不能在当前批次重复加入。
- 作为输入的旧产物会被消费。

执行批次时，系统收集组成、继承输入历史、追加本次事实并生成新产物。历史不保存模型化外观或感官快照。

提示词中的加工链按顺序展示，例如：

```text
切块 → 煎 / 烙（常规） ×2 → 炖 / 焖（充分）
```

只有完全相同且连续的步骤会压缩为 `×N`；非连续重复不会合并。

## 粗粒度标签

每个产物从历史实时派生三个标签：

- 熟化：所有渐进加工中的最高档位；没有渐进加工时为“未加热”。
- 表面加工：所有干热加工中的最高档位；没有干热时为“无”。
- 含水：根据最近一次渐进加工显示“偏湿润”或“偏干爽”；没有渐进加工时为“未体现”。

示例：

```text
状态：熟化程度：充分；表面程度：常规；含水倾向：偏湿润
```

这些标签不累计分数、不参与结算，也不取代完整加工链。

## 菜系倾向

特征食材和部分厨具提供菜系分数。为防止重复加工无限增加分数：

- 同名食材在整道菜中只贡献一次。
- 同一厨具在整道菜中只贡献一次。
- 结果按分数降序排列，提示词最多输出前三项及实际分数。
- 没有得分时显示“自由融合”。

示例：`中餐 4，东南亚菜 2，日料 1`。

## 模型提示词

图片模型和料理评价模型共享同一组事实：

- 当前产物及其组成。
- 按顺序排列并压缩连续重复的加工链。
- 熟化、表面加工和含水三个产物级标签。
- 可选的成品结构角色。
- 得分最高的三个菜系倾向及实际分数。

图片提示词额外提供简短画面要求；评价提示词只要求评价完成度、味道和质地。提示词不输出内部规则解释、详细感官数值或系统预判的绝对外观结果。
