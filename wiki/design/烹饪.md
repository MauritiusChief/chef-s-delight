# 烹饪系统设计

## 文档范围

当前系统的目标是让玩家不依赖固定菜谱，通过组合食材、厨具、操作和加工程度自由制作料理。系统保留加工过程，将料理状态整理成图片生成模型可以理解的提示词。

数据流水线、模型调用、持久化和工程架构另见 `实现.md`；餐厅经营及其他做菜外玩法另见 `经营.md`。

## 核心循环

一次完整的烹饪循环如下：

1. 选择厨具。
2. 从该厨具支持的操作中选择一种操作。
3. 选择基础食材或已经处理过的食材。
4. 将一个或多个食材加入本次处理批次。
5. 对渐进式操作分别设置各食材的加工进度。
6. 执行处理，消耗作为输入的食材，并产生一个新的已处理食材。
7. 将处理结果继续投入其他厨具，形成连续加工。
8. 汇总当前保留的全部成品，计算感官画像和菜系倾向。
9. 将组成、加工历史和汇总结果转换成成品图片提示词。

系统的基本操作单位是一次“厨具 + 操作 + 一批投入”的加工事件。玩家通过串联加工事件形成料理过程。

## 食材模型

### 基础属性

每种基础食材由以下信息描述：

| 属性 | 用途 |
| --- | --- |
| 名称 | 玩家看到的具体食材，例如牛肉、土豆、盐 |
| 展示分组 | 用于选择器分组，例如红肉、叶菜、调味料 |
| 烹饪大类 | 判断操作兼容性、加工外观和基础性质 |
| 基础感官 | 提供食材未经加工时的味觉、气味和质地倾向 |
| 物理特征 | 表示蛋白质、脂肪、水分、糖分和淀粉等反应条件 |

烹饪大类包括：

- 红肉、禽肉、鱼肉、贝类与软体海鲜、蛋
- 结实蔬菜、叶菜、谷物与面食、豆类、面团
- 乳制品、水果、葱蒜与香草、香辛料、坚果与种子
- 液体、油脂、调味料

食材先继承所属大类的感官值和物理特征，再应用具体食材的覆盖值。例如三文鱼在鱼肉大类的基础上有额外丰润感，糖拥有比普通调味料更明确的糖分特征。

当具体食材与大类定义了同一个感官字段时，具体食材值覆盖大类值，而不是与其相加。这是当前原型的实际规则。

### 食材作用

系统根据烹饪大类自动赋予食材作用：

| 大类 | 作用 |
| --- | --- |
| 油脂 | 烹饪油脂 |
| 液体 | 液体 |
| 调味料 | 调味 |
| 香辛料 | 香辛料 |
| 葱蒜与香草 | 芳香配料 |
| 其他大类 | 主体食材 |

“主食底、蛋白质主体、蔬菜、酱汁、配料、点缀”这组角色名称，用于提示词。

## 厨具与操作

厨具决定玩家可以发起哪些操作。部分厨具还会为最终料理提供菜系倾向。

| 厨具 | 可执行操作 |
| --- | --- |
| 菜刀 + 砧板 | 对半、切片、切丝或条、切丁、切块、剁碎 |
| 擦丝器 | 擦碎 |
| 擀面杖 | 压扁、擀薄 |
| 研钵 | 压碎、研磨、捣成泥 |
| 搅拌碗 | 混合、打发、腌制 |
| 平底锅 | 煎或烙、焦糖化、烘香 |
| 炒锅 | 炒、烘香 |
| 汤锅 | 煮或汆煮、炖或焖 |
| 蒸锅 | 蒸 |
| 烤箱 | 烤制或烘焙 |
| 烤架 | 烧烤或炙烤 |
| 油炸锅 | 油炸 |
| 滤网 | 沥干 |
| 串签 | 穿串 |
| 压模 / 饼铛 | 压制成型、煎或烙 |
| 刷子 | 刷油、刷酱或挂汁 |

### 操作兼容性

每种操作分别声明主体食材大类、辅助投入大类和批次必要条件。例如：

- 切配操作主要接受固体食材，不接受液体、油脂和调味料。
- 打发只接受蛋和乳制品。
- 焦糖化接受结实蔬菜、水果和含糖调味料，并要求批次中存在 `sugar` 特征。
- 炖焖接受肉、禽、鱼、结实蔬菜和豆类。
- 烘焙接受面团、蛋、乳制品、水果和结实蔬菜。

操作可以额外接受调味料、香辛料、油脂或液体作为辅助投入，使“食材与油同炒”“肉与高汤同炖”等批次成为可能。辅助投入参与组成和批次反应，但不会自动获得主体食材的熟化、焦香或酥化变化。

煮和炖焖要求批次中包含液体大类，油炸要求包含油脂大类。焦糖化检查食材物理特征，因此糖、洋葱和水果等天然含糖食材均可满足条件。蒸锅自行提供蒸汽，不要求把水作为食材加入批次。

腌制要求批次中包含调味料或香辛料；液体、油脂、芳香配料和乳制品可以作为其他腌料成分，但不能单独满足条件。刷酱或挂汁要求调味料大类，刷油则视为刷子从外部提供油，不要求显式加入油脂。

已处理食材能否投入某项操作，由其第一个主体食材的大类判断；没有主体食材时使用第一个组成食材的大类。

调试流程先在选定厨具下自由建立食材批次，再根据全部投入隐藏不兼容或缺少必要介质的操作。执行时领域层会再次验证相同规则。

## 操作类型

### 即时操作

即时操作没有加工进度，执行后直接产生固定的外观变化：

- 切配：对半、切片、切丝或条、切丁、切块、剁碎、擦碎
- 形态处理：压扁、擀薄、压碎、研磨、捣泥、压制成型
- 组合处理：混合、打发、腌制
- 辅助处理：沥干、穿串、刷油、刷酱或挂汁

例如“切丁”会将投入描述为“切成大小均匀的丁”，“刷酱或挂汁”会描述为“表面均匀覆盖一层酱汁”。

### 渐进式操作

渐进式操作通过五档进度表现熟化、定型、软化、上色和失水：

- 湿热：煮或汆煮、炖焖、蒸
- 干热：煎或烙、炒、烤制或烘焙、烧烤、油炸、烘香、焦糖化

进度从 `0/4` 到 `4/4`：

| 进度 | 一般含义 |
| --- | --- |
| `0/4` | 原始、生鲜或尚未加工 |
| `1/4` | 表层开始变化，内部大多仍接近原始状态 |
| `2/4` | 正常完成，通常已经熟化、定型或达到合适状态 |
| `3/4` | 进一步软化、上色、失水或焦化 |
| `4/4` | 长时间或过度加工，可能松散、干硬、焦黑或结构分解 |

每种渐进式操作都有一组默认描述，也可以按食材大类覆盖。例如同为水煮 `2/4`：

- 红肉完全熟透，但肉纤维仍完整。
- 鱼肉熟透并保持完整分层。
- 鸡蛋蛋白完全凝固，蛋黄形成柔软固态。
- 谷物与面食吸水煮熟并保持弹性。
- 结实蔬菜熟透，同时保留颜色和结构。

因此，加工进度代表可解释的料理状态区间，而不是精确的时间或温度。

## 批次处理

一次加工可以同时接受多个投入项。批次遵循以下规则：

- 所有投入共享同一个厨具和操作。
- 每个投入项可以设置自己的加工进度。
- 一个已处理食材作为单个投入项时，其全部组成食材共享该投入项的新进度。
- 即时操作不记录进度。
- 同一基础食材或同一个已处理食材不能在当前批次重复加入。
- 辅助投入会成为新产物的正式组成，并参与后续感官计算。

例如用炒锅处理鸡肉、大蒜和盐时，可以将鸡肉设为 `3/4`、大蒜设为 `2/4`、盐设为 `0/4`。三者共享“炒”这个操作，但生成各自对应的状态描述。

执行批次时，系统会：

1. 收集所有投入项的基础食材组成。
2. 按名称去重基础食材。
3. 继承输入成品的全部历史步骤。
4. 为本次操作记录每种食材的进度和外观结果。
5. 消耗作为输入的已处理食材。
6. 生成一个包含合并组成与完整历史的新产物。
7. 根据完整历史重新计算新产物的感官画像。

## 已处理食材与加工链

每个已处理食材包含：

| 字段 | 含义 |
| --- | --- |
| ID | 在当前游戏状态中的唯一标识 |
| 标题 | 根据最多三个主体食材自动生成的显示名称 |
| 组成 | 去重后的基础食材列表 |
| 加工历史 | 按执行顺序排列的全部加工事件 |
| 感官画像 | 由组成和完整历史重新计算的结果 |

已处理食材可以继续投入新的批次，从而形成加工链。例如：

1. 使用菜刀将牛肉切块。
2. 使用平底锅将切块牛肉与油煎制。
3. 使用汤锅将煎过的牛肉与高汤、酱油炖煮。

第三步得到的新产物会保留切块、煎制和炖煮三段历史。作为输入的旧产物会从当前列表中消失，避免同一份食材同时存在于加工前后两个状态。

## 感官画像

### 感官维度

当前系统使用十四个维度描述料理：

| 类别 | 维度 |
| --- | --- |
| 基础味觉 | 咸味、甜味、酸味、鲜味 |
| 刺激与气味 | 辣味、辛味、芳香、烟火味 |
| 烹饪风味 | 焦香、血味感知 |
| 质地与含水 | 湿润、干燥、酥脆、丰润 |

每个维度最终限制在 `0-10`。

### 计算顺序

单个已处理食材的感官画像按以下顺序计算：

1. 根据每种基础食材的大类取得基础感官值。
2. 使用具体食材定义覆盖同名感官字段。
3. 累加所有基础食材的结果。
4. 按历史顺序处理每个加工步骤带来的变化。
5. 将所有维度取整并限制在 `0-10`。

历史步骤只影响当时参与该步骤并被 operation 作为主体处理的食材。液体和油脂等辅助投入仍保留在组成中，但不会继承主体的感官变化。较早已经完成的处理会继续影响后续合成产物。

### 加热规则

湿热操作随进度增加主体食材的湿润感。达到较高进度时，也可能因为长时间处理增加少量干燥感，用来表达结构破坏或水分流失；水、高汤等液体介质本身不应用这组变化。

干热操作随进度产生以下变化：

- 中高进度降低湿润感。
- 高进度增加干燥感。
- 随进度增加焦香。
- 烧烤额外增加烟火味。
- 油炸显著增加酥脆。
- 烤制或烘焙、煎或烙在中高进度增加酥脆。

干热和表面酥化效果只作用于规则声明的主体大类。液体、烹饪油脂和普通调味料不会因为与主体处于同一批次就获得焦香或酥脆。

食材特征还会触发批次内反应：

- 红肉、禽肉、鱼肉和海鲜受热后降低血味感知。
- 含糖食材经过中高程度干热后增加甜味和焦香。
- 大蒜和姜受热后辛味下降、芳香上升。
- 干热批次中同时存在脂肪和蛋白质时，根据蛋白质的加工进度增加额外焦香。

### 整体汇总

最终菜品由当前仍保留的全部已处理食材共同构成。整体感官画像通过累加各产物的感官值获得，并再次限制在 `0-10`。

在整体层面，辛味、辣味、酸味和芳香会按一定比例降低血味感知。这表示强烈调味对主观感知的遮盖。

系统提取分数不低于 `2` 的最高七项感官特征，并用“湿润减去干燥”的净值生成整体描述：

- 净值大于 `1`：整体偏湿润。
- 净值小于 `-1`：整体偏干燥。
- 其他情况：湿润与干燥大致平衡。

## 菜系倾向

菜系是根据食材和厨具累积分数得到的提示：

- 特征食材提供菜系分数，例如意面偏意大利菜，咖喱香料偏南亚菜，酱油偏中餐、日料和韩餐。
- 部分厨具提供菜系分数，例如炒锅偏中餐和东南亚菜，研钵偏东南亚菜、南亚菜、中东菜和拉美菜。
- 每个已处理食材的组成及其历史步骤都会参与汇总。
- 最终按得分从高到低排序，在图片提示词中最多使用前三项。
- 没有任何得分时显示“自由融合”。

菜系倾向主要帮助图片模型选择合理的摆盘和视觉语境。

## 图片生成提示词

烹饪系统的直接输出是一段写实成品料理图片提示词，包含：

- 当前全部已处理食材。
- 每个产物的基础食材组成。
- 食材在最后的加工进度、外观和质地。
- 单个产物及整体菜品的感官摘要。
- 得分最高的三个菜系倾向及其相对强度。

提示词还附加固定的画面约束：

- 将全部已处理食材自然组合成一份完整、可食用的菜品。
- 准确保留加工顺序、熟度、外观和质地。
- 使用自然餐桌光线、真实食物质感和近景构图。
- 画面中不出现文字、人物、包装或品牌标志。
